# Design Philosophy

## Lekhak

Version: v0.4

Status: Active Development

Last Updated: June 2026

---

# Purpose

This document defines the visual and experiential principles of Lekhak.

It exists to ensure the product develops a consistent identity over time.

This document should guide:

* User Interface Design
* User Experience Decisions
* Visual Language
* Motion Design
* Future Feature Design

It should be referenced before introducing any major UI changes.

---

# Core Belief

Most writing software focuses on productivity.

Lekhak focuses on memory.

The interface should feel like a place where ideas live and grow.

Not a place where tasks are completed.

---

# What Lekhak Is Not

Lekhak should not feel like:

```text
Project Management Software

Corporate SaaS

Task Tracking Tool

Analytics Dashboard

Admin Panel
```

Avoid interfaces that feel transactional.

Writers are not managing tickets.

They are building stories.

---

# What Lekhak Should Feel Like

Lekhak should feel like:

```text
A Personal Archive

A Creative Workspace

A Living Library

A Memory System

A Place To Return To
```

The emotional response should be:

```text
Calm

Focused

Reflective

Comfortable

Trustworthy
```

---

# Design Pillars

---

## 1. Calm

Writing requires attention.

The interface should never compete with the writer.

Avoid:

```text
Aggressive Colors

Busy Screens

Excessive Motion

Visual Noise
```

Prefer:

```text
Whitespace

Clear Hierarchy

Subtle Contrast

Simple Layouts
```

---

## 2. Memory

Every interface should reinforce continuity.

A writer should always understand:

```text
Where they are

What they were doing

What changed

What comes next
```

The UI should help users reconnect with their work.

---

## 3. Growth

Projects are living things.

Stories evolve.

Ideas mature.

The product should communicate growth over time.

Not just storage.

---

# Visual Identity

---

## Color Philosophy

The palette should feel timeless.

Not trendy.

Not corporate.

Not playful.

---

### Deep Navy

Primary foundation.

Represents:

```text
Focus

Depth

Reflection
```

Used for:

```text
Backgrounds

Primary Surfaces

Navigation
```

---

### Warm Gold

Represents:

```text
Ideas

Creativity

Importance
```

Used for:

```text
Actions

Highlights

Focus States
```

---

### Soft Cream

Represents:

```text
Paper

Reading

Warmth
```

Used for:

```text
Primary Text

Readable Content
```

---

### Natural Green

Represents:

```text
Growth

Progress

Life
```

Used sparingly.

Reserved for:

```text
Positive States

Completion

Success
```

---

# Typography Principles

Typography should prioritize reading.

Not branding.

Avoid:

```text
Decorative Fonts

Handwriting Fonts

Novelty Fonts
```

Prefer:

```text
Modern

Readable

Quiet
```

The content should always be more important than the interface.

---

# Layout Philosophy

The layout should encourage focus.

---

## Navigation

Navigation should remain predictable.

Users should always know:

```text
Where they are

Where to go next
```

---

## Content

Content should receive the majority of screen attention.

UI chrome should remain secondary.

---

## Density

Prefer:

```text
Comfortable
```

over:

```text
Compact
```

Writers spend long periods inside the application.

Visual breathing room matters.

---

# Motion Philosophy

Motion should communicate meaning.

Never decoration.

---

## Good Motion

Examples:

```text
State Changes

Dialog Open

Success Feedback

Page Transitions
```

---

## Bad Motion

Examples:

```text
Constant Animation

Floating Elements

Attention-Seeking Effects

Unnecessary Parallax
```

If motion does not improve understanding, it should not exist.

---

# Future Visual Direction

The following concepts are approved for exploration.

---

## Living Archive

Projects should eventually feel like evolving archives rather than folders.

Concepts:

```text
History

Growth

Memory
```

---

## Memory Timeline

Writers should eventually be able to see:

```text
Project Created

Ideas Added

Notes Updated

Milestones Reached
```

as a journey.

---

## Context Layer

Future interfaces should help users understand:

```text
Why
```

they were working on something.

Not only:

```text
What
```

they worked on.

---

## Connections Layer

Future interfaces should help reveal relationships between:

```text
Projects

Ideas

Notes

Concepts
```

---

## Story Constellation

Long-term concept.

Ideas represented as connected points.

Purpose:

```text
Relationship Discovery

Memory Recall

Creative Exploration
```

This is not currently approved for implementation.

Only exploration.

---

# 3D Design Philosophy

3D should never be decorative.

3D should communicate information.

Approved future use cases:

```text
Story Universe

Memory Constellation

Project Relationships

Writing Journey
```

Avoid:

```text
Rotating Objects

Decorative Models

Pure Visual Effects
```

3D must improve understanding.

# Decision Framework

Before introducing any feature or design change, ask:

### Does this reduce cognitive load?

### Does this help users remember?

### Does this support continuity?

### Does this make writing easier?

### Does this align with a living archive?

If the answer is "No" to most questions, reconsider the change.

---

# Long-Term Design Goal

A writer should open Lekhak after months away and feel:

```text
I know exactly where I left off.
```

The interface should help users reconnect with their work instantly.

That feeling is more important than visual sophistication.
